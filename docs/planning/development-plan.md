## 建议技术栈（待评审）

| 层 | 建议 | 选择理由与待验证项 |
| --- | --- | --- |
| Web 应用 | Next.js App Router、TypeScript | 同一应用承载页面与服务端逻辑，减少独立服务数量；具体依赖版本在启动阶段核实并锁定 |
| 界面与表单 | Tailwind CSS、shadcn/ui、Zod | 复用表格、表单、对话框及校验；先完成清晰流程，再统一视觉细节 |
| 数据、身份、票据文件 | Supabase Postgres、Auth、私有 Storage | 组织／成员权限和文件访问规则同时验证；不得以公开 bucket 简化票据预览 |
| AI | 所选供应商官方 SDK，服务端 API Key 接入 | 第一候选为 OpenAI Responses；供应商、模型及实际图片／PDF能力待 M0 核实，供应商尚未选定 |
| 付款 | PayPal REST Payouts，仅 Sandbox | 验证单笔创建、状态查询和异常；业务层维护持久化付款意图及重复付款防范 |
| 验证 | Vitest、Playwright | 前者覆盖规则、状态和边界；后者覆盖角色、补交、审批和付款页面流程 |
| 候选托管 | Vercel；Supabase 托管数据与文件 | 套餐、运行时限、任务调度、回调与评委访问条件待核实；不预设免费套餐足够 |

AI Key 由项目服务端配置，普通报销人不需要提供 Key。密钥不进入浏览器、票据、日志或仓库。AI 接入详情与运行形态以技术设计为准；首版不同时实现多供应商切换界面。

## 验证层次与演示门槛

### 先测逻辑，再证明真实集成

- **规则与状态单元验证：**使用固定输入／测试替身验证精确货币计算、限额边界、组合问题、失效批准、幂等及状态转换，不调用外部服务。
- **权限与持久化集成验证：**验证真实数据库事务、并发累计占用、组织隔离和私有文件权限；仅前端隐藏按钮不能算通过。
- **页面端到端验证：**使用受控数据完成提交、补交、人工审核、错误恢复与导出；明确哪些服务仍为替身。
- **真实服务验证：**单独记录所选 AI 的调用与 PayPal Sandbox 创建／查询结果。测试替身通过、API 受理和单笔到账分别记录，不能互相替代。

### AI 样本集

计划准备至少 **15 份匿名或合成样本**：10 份正常材料（含清晰图片和 PDF），以及至少 5 份异常材料，覆盖模糊关键字段、重复提交、部分报销、金额冲突、票据中的指令性文字。M0 的少量探索样本不能代替完整样本集验收。

演示自动批准开关开启前，至少达到：

1. 10 份正常材料中，金额、日期、币种三项均正确的样本 **≥ 9/10**；逐样本保存预期值、实际值、来源和人工确认结果。
2. 所有不确定字段和异常情况均得到阻断／补交／人工处理，**异常样本零误付**；不能用平均准确率掩盖某份申请的错误。
3. 来源不存在、输出无法校验、模型超时、拒答或提示注入不会产生付款；字段错误必须被确认流程纠正或被阻断。
4. 上述是待验证的设计门槛，不是当前准确率，也不是生产可靠性承诺。未达标时关闭自动批准演示，先修复或收缩支持票据范围。

### 核心验收不得降级

权限越界、重复付款、错误收款人、过期批准执行、未知支付状态被当作到账、并发绕过额度，均以 **零失误** 作为本次受控验收的通过条件。发现一例即阻断对应功能交付；测试通过不宣称覆盖所有真实世界情形。

## 延迟与范围调整

- 先保留“一份清晰小额单自动处理”“一份模糊大额单补交后人工审批”“重复操作不重复付款”三个可运行场景。
- 可先简化视觉装饰、复杂筛选、统计展示和 CSV 字段；如需将原定 P0 能力移出交付，先同步 PRD 并明确范围变更，不静默漏项。
- AI 质量不足时收窄文件种类／页数或保持人工审核；不得将猜测字段作为确定事实。PDF 如无法可靠支持，需明确评审调整后的范围。
- PayPal 权限或真实 Sandbox 流程阻塞时优先处理，不能用模拟支付宣称已完成比赛所需集成。
- 托管后台任务不可靠时，先调整执行形态并验证恢复；不得改用内存任务承载未完成付款。
- 无论时间压力多大，都保留服务端权限、私有票据、有效版本批准、支付幂等、未知结果对账与单笔状态核实。
